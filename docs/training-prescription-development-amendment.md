# Proposed Task 47–50 development sequencing amendment

**Status:** approved by the owner — 2026-10-23.
Decision: "Aprovar desenvolvimento isolado; manter requisitos de liberação".
The canonical sequencing requirements are updated to reflect this exception.
This is not a professional approval, review record or evaluation seal.

## Problem

Owner domain decisions now specify inputs, audience, source research, accounting
and rejection behavior. EXT-CA-AI-02.18/19 and Task 47/48 still require approved
contracts, reviewed retrieval feasibility and a sealed independent evaluation plan
**before implementing the production gate**. Those actual reviews and seal do
not exist. Choosing references and assigning the instructor role does not satisfy
them; coding synthetic tests cannot supply them.

Task 47 development helpers can proceed under current scope. Implementing Tasks
48–50 before those prerequisites requires an explicit sequencing decision.

## Exact proposed exception

Permit implementation of the Tasks 48–50 contracts, validator, integration and UI
in an isolated development scope using clearly synthetic development policies and
offline fixtures before professional approval, reviewed feasibility and evaluation
sealing. These changes must not enable the new prescription-qualification feature
for real students or import synthetic approvals into operational artifacts.

Keep the existing release requirements: real policy/dictionary/input/accounting
approval, source permissions and applicability, reviewed six-passage feasibility,
independent held-out custody/sealing, positive and negative controls, actual-
deployment evaluation and named scoped release sign-offs must all exist before
the new feature is enabled for real students. No invented reviewers, clinical
ranges, credentials, diagnoses or paid resources are permitted.

The evaluation design remains prespecified from Task 45. Any concrete cases or
answers seen by implementers are development material. The independent evaluator
must create/retain a genuinely untouched held-out set and seal its reference
judgments and thresholds before evaluation; exposed/tuned cases must be replaced.
The development exception is not an independent evaluation or a Task 51 pass.

## Canonical/task edits if approved

| Location | Proposed change |

| Task 47 design exit / Task 48 prerequisites | Distinguish development entry from operational enablement; development entry may use draft contracts and synthetic fixtures, while real approval/feasibility/seal remain release prerequisites. |

| Task 51 | No waiver: independent actual-deployment evaluation and scoped sign-offs remain mandatory. |
| Execution/domain specifications | Synchronize only the sequencing distinction; keep identity/privacy, evidence, permissions, instructor review and unsupported-candidate rejection unchanged. |

No change to the requirement for independent assessments is proposed. An owner
instruction to let a single instructor perform all responsibilities alone does
not establish the required independence or complete professional approval. That
would require a separate explicit governance decision and is outside this
sequencing exception.
